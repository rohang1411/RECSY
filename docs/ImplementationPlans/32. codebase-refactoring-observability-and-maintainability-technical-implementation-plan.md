## 1. Executive Summary & Big-Tech Architectural Philosophy

Modern distributed production systems often succumb not to spectacular architectural collapse, but to the slow accumulation of latent contract mismatches, swallowed error states, leaky connection singletons, and unmonitored failure modes. When error types diverge across route boundaries, autonomous agents and human on-call engineers are forced to reverse-engineer stack traces rather than acting on deterministic telemetry.

This Master Implementation Plan establishes a rock-solid, production-grade technical execution roadmap grounded in the architectural consensus documented in [`docs/architecture/refactoring_and_maintainability_plan.md`](file:///C:/Users/rohan/.gemini/antigravity/worktrees/mobile_recommender/refactor_codebase_maintainability/docs/architecture/refactoring_and_maintainability_plan.md).

Written from the perspective of a Senior Staff Software Engineer at a hyperscale tech company, this plan prioritizes:

1. **Contract Invariance & Strict Typing:** Zero ambiguous response bodies; absolute separation of machine-readable error codes and human-safe sanitized strings.
2. **Defensive Async Resilience:** Critical user journeys (e.g. conversational smartphone recommendations) must never crash due to timeouts or rejections in optional enrichments (e.g. semantic query embeddings).
3. **Observability Honesty:** Fallback states must never report false health status (`'pass'`) when underlying data layers are offline or corrupted. Health radars must accurately reflect metric degradation.
4. **PostgreSQL & Pooler Concurrency Safety:** Strict adherence to database column types, enum definitions, transaction boundaries under Supavisor transaction poolers, and explicit connection pool lifecycle teardown hooks.
5. **Deterministic Verification Gates:** Quantifiable SLAs across retrieval recall, tail latency, recommendation ranking quality, and zero-warning codebase hygiene.

### 1.1 Core Subsystem Topology

RECSY v2 follows a pipeline-oriented, event-resilient architecture across six core subsystems:

1. **Next.js 15 App Router Gateways:** Edge and Node runtimes handling API requests with security headers, same-origin validation, and request-id tracing.
2. **Quota & Metering Engine (`src/services/metering`):** Two-phase query leases (`QueryLease.reserve()` and `commit()`) ensuring zero double-charging, with automatic idempotent refunds on failure.
3. **Model Gateway (`src/services/llm`):** Multi-model router with Gemini 2.5 Flash / 2.5 Pro cascading, circuit breaking, JSON repair sanitizer, and thinking budget governors.
4. **Hybrid Retrieval Engine (`src/services/retrieval`):** Dense embeddings + pgvector HNSW combined with tsvector GIN, Reciprocal Rank Fusion (RRF), Maximal Marginal Relevance (MMR) diversification, and Corrective RAG (CRAG) gating.
5. **Scorecard Engine (`src/services/scorecard`):** Multi-aspect phone scoring with time-decay recency weighting and confidence-weighted multi-criteria ranking.
6. **Command Center Radar (`src/services/internal`):** Unified observability scanning catalog integrity, orphan chunks, and telemetry in single-pass CTE scans.

### 2.1 Multi-Agent Debate Consensus Record

The forensic debate record established the following core resolutions:

- **Round 1 (Client Error Handling & Contract Parity — `src/lib/metered-fetch.ts`):**  
  Agent 1 proposed generic polymorphic error wrappers; Agent 3 attacked this as over-engineering. The real issue was contract mismatch: `http-errors.ts` emitted flat `{ code, message }` JSON payloads, while standard HTTP error handlers or Next.js emitted `{ error: string }`, but `handleMeteredError` only inspected `payload.error.code`. Consensus: Normalize error extraction to handle flat `{ code, message }`, nested `{ error: { code, message } }`, and string `{ error: string }` without mutating UI contract types.
- **Round 2 (Recommender Async Promise Rejection Safety — `src/services/recommender/run-recommendation.ts`):**  
  Agent 1 proposed wrapping the entire recommender in a retry loop; Agent 2 cited tail latency penalties. Agent 3 pinpointed the exact bug: `embedPromise.catch(() => undefined)` was called on a detached promise reference. If `llm.embed()` rejected during high concurrency or quota exhaustion, `await embedPromise` threw an unhandled promise rejection, crashing `/api/recommend`. Consensus: Chain `.catch()` directly onto the assigned promise reference, emit a structured warning, and proceed safely with aspect heuristics.
- **Round 3 (Zod Validation Response Standardization — `src/services/metering/http-errors.ts`):**  
  Agent 1 proposed nested JSON schema validation trees; Agent 3 proved this breached client compatibility. In `http-errors.ts`, `POST /api/ask` returned `{ code: 'VALIDATION', message: string }`, while `POST /api/recommend` returned `{ code: 'VALIDATION', message: object }` (the output of `err.flatten()`), breaking any consumer expecting `typeof message === 'string'`. Consensus: Standardize `message` to always be a string (`err.issues[0]?.message ?? 'Invalid request body'`) and attach structured details to `details: err.flatten()`.
- **Round 4 & 4B (PostgreSQL Enum & Numeric Alignment — `src/services/internal/integrity-audit.ts`):**  
  Agent 3 uncovered two critical PostgreSQL bugs: (1) `p.msrp_usd ~ '^[0\.]+$'` threw syntax errors on PostgreSQL because `~` is undefined for `numeric(10, 2)` columns without `::text` casting; (2) `zombie_ingest_runs` queried `r.status = 'running'`, but PostgreSQL enum `ingest_status` strictly defines `('started', 'success', 'failed', 'skipped')` — comparing to an unknown literal causes PostgreSQL to throw `ERROR: invalid input value for enum ingest_status: "running"`. Additionally, fallback reports used a static module-load timestamp and reported `status: 'pass'`. Consensus: Cast `p.msrp_usd::text`, query `WHERE r.status::text IN ('started', 'running') AND r.started_at < NOW() - INTERVAL '2 hours'`, generate fresh `checkedAt: new Date().toISOString()`, and report `status: 'fail'` on fallback.
- **Round 5 (CI Test Discovery Coverage — `vitest.config.ts`):**  
  Agent 1 proposed directory restructuring; Agent 3 noted directory churn creates merge conflicts. The actual defect was `vitest.config.ts` omitted `'scripts/**/*.test.ts'`, ignoring critical CI gates (`scripts/ci-retrieval-gate.test.ts` and `scripts/seed/creator-profiles.test.ts`). Consensus: Add `'scripts/**/*.test.ts'` to `vitest.config.ts`'s `include` array.
- **Round 6 (Command Center UI Honesty & React Runtime Contract Safety — `src/app/internal/command-center/_components/system-integrity-radar.tsx`):**  
  Agent 3 identified that `system-integrity-radar.tsx` unconditionally rendered `<CheckCircle>` in emerald green for every metric regardless of counts and ignored `codeHygieneStatus`. Furthermore, passing non-string messages to React threw `Objects are not valid as a React child`. Consensus: Dynamically render amber `<AlertTriangle>` for warnings and rose `<ShieldAlert>` for failures, render AST code hygiene state accurately, and enforce string-only message contracts.

### 2.2 Immutable Architectural Invariants

Every work package in this plan must strictly maintain the following six architectural invariants:

1. **Invariant 1: Error Contract Homogeneity**
   - Every API error response must strictly emit `{ code: string, message: string }`, where `message` is guaranteed to be a string. Additional diagnostics must be provided under `details: Record<string, unknown>`. No route may emit nested `{ error: { code } }` or raw JSON object error messages that crash React renderers.
2. **Invariant 2: Graceful Degradation on Async Rejection**
   - Optional enrichments (e.g., semantic vector embeddings for query intent) must never be allowed to throw unhandled promise rejections or abort the primary recommender flow. Promises must be chained directly at creation with structured logging and fallback to aspect heuristics.
3. **Invariant 3: Observability Honesty**
   - Health monitors, integrity audits, and radar widgets must never report synthetic `'pass'` statuses when the underlying database is unreachable or queries fail. Fallback reports must explicitly report `'fail'` and accurately capture elapsed milliseconds and timestamps.
4. **Invariant 4: PostgreSQL Schema & Enum Type Fidelity**
   - SQL queries and CTEs executed through the `postgres` driver must respect column types and enum constraints. Text regex operators (`~`, `!~`) must be cast (`col::text`), and enum literals must exist in the PostgreSQL `pg_type` catalog (`ingest_status`: `'started'`, `'success'`, `'failed'`, `'skipped'`).
5. **Invariant 5: Two-Phase Metering Lease Safety**
   - Any metered request admitted via `QueryLease.reserve()` that encounters an unhandled exception before `lease.commit()` must idempotently refund the lease (`lease.refund(code)`). Uncommitted leases must never leak quota or double-charge users.
6. **Invariant 6: Universal Test Discovery & Hygiene**
   - Test discovery in Vitest must cover all repository test surfaces: `src/**/*.{test,spec}.{ts,tsx}`, `test/security/**/*.test.ts`, and `scripts/**/*.test.ts`. Zero ESLint warnings and zero TypeScript diagnostics are tolerated in CI.

   ```ts
   export async function closeDb(options?: { timeout?: number }): Promise<void> {
     _db = null;
     if (_client !== null) {
       const clientToClose = _client;
       _client = null;
       await clientToClose.end({ timeout: options?.timeout ?? 5 }).catch(() => undefined);
     }
   }
   ```
2. **Lightweight Connection Health Ping (`pingDatabase`):** Export `pingDatabase(timeoutMs = 2000): Promise<{ ok: boolean; latencyMs: number; error?: string }>` in [`src/services/db/client.ts`](file:///C:/Users/rohan/.gemini/antigravity/worktrees/mobile_recommender/refactor_codebase_maintainability/src/services/db/client.ts):
   ```ts
   export async function pingDatabase(
     timeoutMs = 2000,
   ): Promise<{ ok: boolean; latencyMs: number; error?: string }> {
     const t0 = performance.now();
     try {
       const client = getPostgres();
       let timer: NodeJS.Timeout | undefined;
       await Promise.race([
         client`SELECT 1 as ping`,
         new Promise<never>((_, reject) => {
           timer = setTimeout(() => {
             reject(new Error(`Database ping timed out after ${timeoutMs}ms`));
           }, timeoutMs);
           if (typeof timer.unref === 'function') {
             timer.unref();
           }
         }),
       ]);
       if (timer) clearTimeout(timer);
       return { ok: true, latencyMs: Math.round((performance.now() - t0) * 10) / 10 };
     } catch (err) {
       return {
         ok: false,
         latencyMs: Math.round((performance.now() - t0) * 10) / 10,
         error: err instanceof Error ? err.message : String(err),
       };
     }
   }
   ```

### 4.2 Phase 2 (P1): 8-Dimension Typed Error Taxonomy, Deterministic Status Codes & Shared Client Schema Synchronization

#### 4.2.1 Problem Statement

When errors occur across edge proxies, rate limiters, metering admissions, LLM providers, and PostgreSQL transactions, they must not collapse into generic 500 errors or inconsistent payload shapes. An autonomous agent or human client must be able to branch deterministically based on the error code.

#### 4.2.2 Formal 8-Dimension Taxonomy Matrix

| Error Class             | Diagnostic Identifier     | HTTP Status                | Retry-After Header                | Lease Action              | Client UI Treatment                |
| :---------------------- | :------------------------ | :------------------------- | :-------------------------------- | :------------------------ | :--------------------------------- |
| **1. Validation**       | `ZodError` / Bad Input    | `400 Bad Request`          | None                              | Refund (`validation`)     | Inline field error or Toast        |
| **2. Quota Exhaustion** | `QuotaDeniedError`        | `402 Payment Required`     | `2s` (if inflight), None (if cap) | Refund (`quota_denied`)   | Quota Upgrade / Modal dialog       |
| **3. Rate Limit**       | `RateLimitError`          | `429 Too Many Requests`    | `60s` (or computed delta)         | Refund (`rate_limited`)   | Inline countdown badge             |
| **4. BYOK Failure**     | `ByokError` (invalid key) | `401 Unauthorized` / `429` | Provider-specific                 | Refund (`byok_rejected`)  | Settings callout / BYOK modal      |

### 4.3 Phase 3 (P2): True Streaming NLI Entailment Telemetry & Streaming Hallucination Guard Parity

#### 4.3.1 Problem Statement & Forensic Gap

In non-streaming `/api/ask` ([`src/services/chat/answer.ts:398-428`](file:///C:/Users/rohan/.gemini/antigravity/worktrees/mobile_recommender/refactor_codebase_maintainability/src/services/chat/answer.ts)), answers generated by the LLM undergo sentence-by-sentence Natural Language Inference (NLI) verification via `verifyGeneratedAnswerEntailment()`. This calculates an accurate `entailmentScore` and `unsupportedClaimCount`, strips unentailed citations, and persists these metrics to the `chat_queries` table for production drift monitoring.

In contrast, in streaming `/api/ask` ([`src/services/chat/answer-stream.ts:371-375`](file:///C:/Users/rohan/.gemini/antigravity/worktrees/mobile_recommender/refactor_codebase_maintainability/src/services/chat/answer-stream.ts)), the final result event emits:

```ts
entailmentScore: 1.0,
unsupportedClaimCount: citationRepairs,
```

**Forensic Reality:** Streaming answers currently report synthetic `1.0` entailment scores to `chat_queries`, completely masking streaming hallucination rates from production observability! Furthermore, if `CitationStreamGuard` stripped phantom citation IDs but the text contained unentailed claims, `llm.storeChat()` could cache unentailed answers.

#### 4.3.2 Technical Specification

1. **Post-Stream Sentence NLI Evaluation:** In `runPhoneQnaStream`, once the LLM stream completes and `guard.flush()` is finished, run `verifyGeneratedAnswerEntailment` across `guard.emitted` against the retrieved chunk premises:
   ```ts
   const nliResult = verifyGeneratedAnswerEntailment(
     guard.emitted,
     retrieval.chunks.map((c) => ({ chunkId: c.chunkId, text: c.text })),
   );
   ```
2. **Truthful Telemetry Emission:** In the `final` stream event and in `persistChatQuery`:
   ```ts
   entailmentScore: nliResult.entailmentScore,
   unsupportedClaimCount: citationRepairs + nliResult.unsupportedClaims,
   ```
3. **Cache Poisoning Prevention:** Suppress `llm.storeChat()` caching whenever `citationRepairs > 0` OR `nliResult.unsupportedClaims > 0`. Only 100% verified entailed answers are committed to the semantic LLM cache.
4. **Test Fixture Compatibility:** Update mock chunk premises in test suites (`src/services/chat/answer-stream.test.ts`) so mock retrieval chunks include lexical tokens matching mock generated answers, ensuring true NLI entailment passes deterministically.
