## 1. Executive Architecture & Mission Statement

### 1.1 The Operational Paradox of Small-Scale AI Systems

Large-scale AI applications (e.g., web search over billions of pages or collaborative filtering across millions of users) optimize for **candidate reduction and retrieval precision**. In contrast, RECSY v2 operates in a specialized **small-corpus, high-precision domain**:

- **Recommender Catalog:** $N \approx 50 - 500$ distinct active smartphone models.
- **RAG Corpus:** $K \approx 15 - 100$ crawled sources ($20 - 50$ segmented chunks) per individual phone.
- **User Interaction Matrix:** $>99.9\%$ sparse, pure zero-shot cold start for shopping sessions.

In this regime, traditional web-scale paradigms fail catastrophically:

1. **Collaborative Filtering Collapses:** Matrix factorization ($U \times V^T$) suffers rank collapse because user interaction matrices contain virtually no overlapping feedback.
2. **Dense Vector Cramping:** In small vector spaces (25 chunks), cosine similarities cluster tightly between $0.62$ and $0.78$. Unanswerable questions or hallucination traps still yield top-$k$ hits that appear statistically relevant.
3. **Lexical Fragility:** PostgreSQL Full-Text Search (`tsvector @@ websearch_to_tsquery`) frequently returns zero hits due to strict vocabulary mismatches between user queries and reviewer phrasing.
4. **Parametric Hallucination:** Under standard prompting, instruction-tuned LLMs fabricate features when presented with marginally relevant chunks, attaching valid chunk citation tags to false assertions.

### 1.2 System Blueprint

This master implementation plan establishes an end-to-end, deterministic, production-grade architecture that resolves these fundamental vulnerabilities at their root causes.

### WP-01: Recommender Core: Calibrated Bayesian Shrinkage & Multi-Currency Normalization

#### 1. Root Cause Resolution: Empirical Bayesian Shrinkage

In small corpora, aspect ratings derived from $N_i < 3$ sources have high epistemic variance. The current formula in [`src/services/recommender/match.ts`](file:///C:/Users/rohan/.gemini/antigravity/worktrees/mobile_recommender/low_data_rag_research/src/services/recommender/match.ts#L270-L274) leaves scores uncalibrated.

We replace the heuristic shrinkage with formal **Empirical Bayes James-Stein Shrinkage**:
$$\hat{s}_{i, a} = \frac{N_{i, a}}{N_{i, a} + N_0} \bar{x}_{i, a} + \frac{N_0}{N_{i, a} + N_0} \mu_0$$
Where:

- $\mu_0 = 5.0$ (Neutral baseline prior).
- $N_{i, a}$ is the verified citation count for phone $i$ on aspect $a$.
- $N_0 = 5.0$ (Pseudo-observation confidence parameter).
- When $N_{i, a} = 0$, confidence $c = 0.0 \implies \hat{s}_{i, a} = 5.0$ exactly.
- When $N_{i, a} = 5$, confidence $c = 0.5 \implies \hat{s}_{i, a} = 5.0 + 0.5(\bar{x}_{i, a} - 5.0)$.
- When $N_{i, a} \ge 20$, confidence $c \ge 0.8 \implies \hat{s}_{i, a} \approx \bar{x}_{i, a}$.

**Implementation in `src/services/recommender/match.ts`:**

```typescript
export const BAYESIAN_PRIOR_MEAN = 5.0;
export const BAYESIAN_PSEUDO_OBSERVATIONS = 5.0;

export function calculateBayesianCalibratedScore(
  rawScore: number,
  citationCount: number,
  priorMean: number = BAYESIAN_PRIOR_MEAN,
  pseudoObs: number = BAYESIAN_PSEUDO_OBSERVATIONS,
): { calibratedScore: number; confidence: number } {
  const n = Math.max(0, citationCount);
  const confidence = n / (n + pseudoObs);
  const calibratedScore = confidence * rawScore + (1 - confidence) * priorMean;
  return { calibratedScore, confidence };
}

export function weightedAspectScore(
  scores: ReadonlyMap<AspectName, number>,
  weights: ReadonlyMap<AspectName, number>,
  confidences?: ReadonlyMap<AspectName, number>,
  citationCounts?: ReadonlyMap<AspectName, number>,
): number {
  let acc = 0;
  for (const name of ASPECT_NAMES) {
    const w = weights.get(name) ?? 0;
    const s = scores.get(name) ?? BAYESIAN_PRIOR_MEAN;
    const count =
      citationCounts?.get(name) ?? (confidences ? Math.round(confidences.get(name)! * 10) : 0);
    const { calibratedScore } = calculateBayesianCalibratedScore(s, count);
    acc += w * calibratedScore;
  }
  return acc;
}
```

export interface ExchangeRates {
  readonly base: 'USD';
  readonly rates: Record<string, number>; // e.g. { EUR: 0.92, INR: 86.5, GBP: 0.79 }
}

export function normalizeToUsd(amount: number, currency: string, rates: ExchangeRates): number {
  if (currency.toUpperCase() === 'USD') return amount;
  const rate = rates.rates[currency.toUpperCase()];
  if (!rate || rate <= 0) {
    throw new ValidationError(`Unsupported or invalid currency code: ${currency}`);
  }
  return amount / rate;
}

export function convertFromUsd(
  amountUsd: number,
  targetCurrency: string,
  rates: ExchangeRates,
): number {
  if (targetCurrency.toUpperCase() === 'USD') return amountUsd;
  const rate = rates.rates[targetCurrency.toUpperCase()];
  if (!rate || rate <= 0) {
    throw new ValidationError(`Unsupported or invalid currency code: ${targetCurrency}`);
  }
  return amountUsd * rate;
}

### WP-03: Pre-Inference Corrective RAG (CRAG) & Abstention Gate

#### 1. Mathematical Grounding Gate Formulation

In low-data RAG, instruction-tuned models hallucinate when presented with noisy chunks. We implement a deterministic **Corrective RAG (CRAG) Pre-Inference Gate** in `src/services/chat/crag-gate.ts`:

Let $C = \{c_1, c_2, \dots, c_k\}$ be the retrieved chunks for phone $p$ and query $q$.
Let $\text{sim}(q, c_i) = 1 - \text{cosine\_distance}(\vec{e}_q, \vec{e}_{c_i})$.
Let $S_{\max} = \max_{c_i \in C} \text{sim}(q, c_i)$.
Let $S_{\text{fts}} = \text{count}(\text{FTS matching chunks})$.

The gate decision rule:

$$
\text{Action}(q, C) = \begin{cases}
\text{SYNTHESIZE} & \text{if } S_{\max} \ge 0.72 \text{ or } S_{\text{fts}} \ge 1 \\
\text{SPEC\_FALLBACK} & \text{if } S_{\max} < 0.72 \text{ and } q \text{ targets a spec attribute} \\
\text{ABSTAIN} & \text{if } S_{\max} < 0.72 \text{ and } S_{\text{fts}} = 0
\end{cases}
$$

#### 2. Implementation in `src/services/chat/answer.ts`

```typescript
export const CRAG_SIMILARITY_THRESHOLD = 0.72;

export function evaluateRetrievalConfidence(retrieval: RetrievalResult): {
  action: 'synthesize' | 'abstain';
  maxSimilarity: number;
  reason?: string;
} {
  if (retrieval.chunks.length === 0) {
    return { action: 'abstain', maxSimilarity: 0, reason: 'zero_chunks' };
  }

  // Raw cosine similarity preserved via vectorSimilarity on RetrievedChunk
  // or via retrieval.debug.vector.maxSimilarity (calculated in vector.ts as 1 - distance)
  const maxSim =
    retrieval.debug?.vector?.maxSimilarity ??
    Math.max(
      ...retrieval.chunks.map((c) => (c as any).vectorSimilarity ?? (c.score > 0.1 ? c.score : 0)),
      0,
    );
  const ftsHits = retrieval.debug?.fts?.count ?? 0;

  if (maxSim >= CRAG_SIMILARITY_THRESHOLD || ftsHits > 0) {
    return { action: 'synthesize', maxSimilarity: maxSim };
  }

  return {
    action: 'abstain',
    maxSimilarity: maxSim,
    reason: `insufficient_semantic_confidence (max=${maxSim.toFixed(3)} < ${CRAG_SIMILARITY_THRESHOLD})`,
  };
}
```

- Consumes **0 LLM generation tokens**.
- Guaranteed **0 hallucinations**.

### WP-04: Contextual Chunk Ingestion (Anthropic Formulation)

#### 1. Eliminating Cross-Entity Contamination

In tech review videos, creators frequently compare multiple devices in a single sentence:
_"Compared to the Galaxy S24, the Pixel 8a runs significantly hotter during 3DMark testing."_
Blind sentence splitting leaves chunks without subject anchors. When ingested for Galaxy S24, it corrupts the S24's thermal aspect scorecard.

#### 2. Ingestion Pipeline Modification (`src/services/ingest/chunking.ts`)

During ingestion, every chunk must be augmented with an LLM-synthesized or template-derived **50-token contextual header**:

```typescript
export interface ContextualChunkHeader {
  phoneBrand: string;
  phoneModel: string;
  sourceCreator: string;
  sourceType: string;
  primarySubject: string;
  temporalOffset?: string;
}

export function formatContextualPreamble(header: ContextualChunkHeader): string {
  return [
    `[TARGET PHONE: ${header.phoneBrand} ${header.phoneModel}]`,
    `[SOURCE: ${header.sourceCreator} (${header.sourceType})]`,
    `[PRIMARY SUBJECT: ${header.primarySubject}]`,
    header.temporalOffset ? `[VIDEO TIMESTAMP: ${header.temporalOffset}]` : '',
    '---',
    '',
  ]
    .filter(Boolean)
    .join('\n');
}
```

The database stores:

- `phone_chunks.chunk_text`: The contextualized text (used for embedding generation and full-text search indexing).
- `phone_chunks.raw_excerpt`: The clean original verbatim excerpt (used for UI citation cards and display).

### WP-05: Dynamic Vocabulary Expansion & Hybrid Reciprocal Rank Fusion

#### 1. Resolving PostgreSQL FTS Sparsity in Small Corpora

PostgreSQL Full-Text Search fails when colloquial user queries differ from technical review vocabulary. We implement a lightweight **Domain Synonym Dictionary** in `src/services/retrieval/synonyms.ts`:

```typescript
export const SMARTPHONE_DOMAIN_SYNONYMS: Readonly<Record<string, readonly string[]>> = {
  pwm: ['flicker', 'eye strain', 'display frequency', 'oled dimming', 'headache'],
  battery: ['endurance', 'screen on time', 'sot', 'drain', 'mah', 'battery life'],
  charging: ['fast charge', 'supervooc', 'wattage', 'charging speed', 'wired charging'],
  camera: ['sensor', 'shutter lag', 'low light', 'dynamic range', 'megapixels', 'optical zoom'],
  performance: ['throttling', 'antutu', 'geekbench', 'framerate', 'lag', 'stutter', 'chipset'],
  durability: ['drop test', 'scratches', 'gorilla glass', 'build quality', 'bend test'],
  compact: ['small', 'one-handed', 'pocketable', 'lightweight', 'form factor'],
};

export function expandSearchQuery(query: string): string {
  const tokens = query.toLowerCase().split(/\s+/);
  const additions: string[] = [];

  for (const token of tokens) {
    const synonyms = SMARTPHONE_DOMAIN_SYNONYMS[token];
    if (synonyms) {
      additions.push(...synonyms.slice(0, 3));
    }
  }

  if (additions.length === 0) return query;
  return `${query} OR ${additions.join(' OR ')}`;
}
```

#### 2. Reciprocal Rank Fusion (RRF) Tuning

In `src/services/retrieval/hybrid.ts`, fuse dense vector search and sparse FTS via standard RRF with $k_{\text{rrf}} = 60$:
$$\text{RRF\_Score}(d) = \frac{w_{\text{vec}}}{60 + r_{\text{vec}}(d)} + \frac{w_{\text{fts}}}{60 + r_{\text{fts}}(d)}$$
Where $w_{\text{vec}} = 0.70$ and $w_{\text{fts}} = 0.30$.

### WP-06: Post-Generation NLI Entailment Gate & Citation Stream Guard

#### 1. Sentence-Level Entailment Verification

To eliminate false citations, execute sentence-level Natural Language Inference (NLI) using Gemini Flash or a fast cross-encoder.
For each sentence $S_j$ in the generated output bearing citation $[c:k]$:

- Premise: Text of chunk $c_k$.
- Hypothesis: Sentence $S_j$.
- Classification: `ENTAILMENT`, `NEUTRAL`, or `CONTRADICTION`.

If classification is `NEUTRAL` or `CONTRADICTION`:

- Strip the fake citation tag $[c:k]$.
- If the ungrounded assertion is central to the answer, re-prompt the LLM with an explicit negative constraint.
- Log an `unsupported_claim` telemetry event to `chat_queries`.

#### 2. Streaming Citation Guard (`src/services/chat/citation-stream-guard.ts`)

Prevent raw, unverified chunk tags from reaching the client:

- Buffer tokens until citation syntax `[c:uuid]` completes.
- Verify `uuid` exists in the admitted chunk set $C_{\text{retrieved}}$.
- If invalid, discard tag and emit clean text.

### WP-08: Low-Overhead Media & YouTube Verification Engine

#### 1. In-Memory Regex Format Verification (0 CPU, 0 Network)

- **YouTube Channel IDs:** Must match `/^UC[a-zA-Z0-9_-]{22}$/`.
- **YouTube Video IDs:** Must match `/^[a-zA-Z0-9_-]{11}$/`.

#### 2. Asynchronous YouTube oEmbed HEAD Verification

Never scrape heavy YouTube HTML watch pages to verify if a video is alive (which takes $1.5\text{s}$ and downloads $500\text{KB}$).
Use YouTube's official **public oEmbed endpoint** with an HTTP `HEAD` request:
`https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=${videoId}&format=json`

- **Response:**
  - `HTTP 200 OK`: Video is public and accessible.
  - `HTTP 404 Not Found`: Video deleted, account suspended, or URL malformed.
  - `HTTP 401 / 403`: Video private or region restricted.
- **Bandwidth Consumption:** $< 1\text{KB}$ per check.
- **API Quota:** **0 tokens, 0 Gemini/YouTube API keys consumed**.
- **Execution Strategy:** Run via background cron with `p-limit(3)` concurrency and cache results with a 24-hour TTL in `sources.verification_status`.

### WP-10: Adverse Scenarios, Edge Cases & Security Hardening

#### 1. Domain Classifier & Inappropriate Request Defense

Add a strict domain classification gate to `extractUserRequirements` (`src/services/recommender/extract-requirements.ts`):

```typescript
export interface DomainGateResult {
  isSmartphoneDomain: boolean;
  isAdversarialJailbreak: boolean;
  rejectionReason?: string;
}

export function evaluateRequestDomain(userMessage: string): DomainGateResult {
  const m = userMessage.toLowerCase();

  // Adversarial jailbreak detection
  if (/(?:ignore previous|system prompt|reveal your instructions|dan mode|jailbreak)/i.test(m)) {
    return {
      isSmartphoneDomain: false,
      isAdversarialJailbreak: true,
      rejectionReason: 'adversarial_injection',
    };
  }

  // Out of domain queries (laptops, cars, appliances, general trivia)
  if (
    /\b(?:laptop|macbook|notebook|desktop|gpu|rtx\s*\d{4}|car|refrigerator|dishwasher|tv|television)\b/i.test(

    )
  ) {

      isSmartphoneDomain: false,
      isAdversarialJailbreak: false,
      rejectionReason: 'out_of_domain_product',
    };
  }

  return { isSmartphoneDomain: true, isAdversarialJailbreak: false };
}
```
